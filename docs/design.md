# design.md

## 解決する問題

作者がノベルゲームの内容ではなく、ティラノスクリプトのDSLやタグ記法を意識しなければならない問題。

作者はシナリオ（セリフ、地の文、展開、分岐）を考えたいのに、タグの記法や素材指定の書式を思い出す作業が挟まり、思考が途切れる。

## 解決方法

自然言語で記述されたシナリオをClaude Code Skillが解釈し、ティラノスクリプトへ変換する。

入力は音声文字起こしでも、直接書いた文章でも、脚本や箇条書きでも構わない。独自エンジンや独自記法は作らない。実行はティラノスクリプトにそのまま任せる。

## 重要な前提

DSLそのものを廃止するわけではない。ティラノスクリプトは実行形式として利用し続ける。

変更するのは、**作者がDSLを直接記述しなければならないという前提**である。

## 設計上の中心

```text
人間はシナリオを自然言語で表現する
AIはティラノスクリプトへ変換する
ティラノは編集・実行する
```

- 人間（作者）だけがシナリオの内容を決める。語っても、書いても、構成を示してもよい
- AI（Skill）は表現された内容をティラノスクリプトの記法へ写す。創作・推敲・補完はしない
- ティラノスクリプトが唯一の実行基盤。ランタイムを再発明しない

## 正本

初期段階では、入力テキストと生成された`.ks`のどちらを正本とするかを固定しない。

- 入力テキストは作者の表現の記録であり、最終的な編集は`.ks`で行う可能性が高い
- 本ツールは初稿生成を主目的とするため、生成後の`.ks`を人間が直接編集する運用を許容する
- したがって、**再生成によって手修正を上書きする設計にはしない**。出力先に既存の`.ks`がある場合、Skillは上書き前に確認する

## 制約

- 自然言語の意図は完全には復元できない
- 入力は誤り（音声認識の誤変換、書きかけの文章など）を含みうる
- 細かな局所編集は`.ks`を直接編集する方が速い（本ツールは初稿生成に向き、微修正には向かない）
- 一発で完成品を作るものではない
- AIの解釈結果は作者による確認を必要とする
