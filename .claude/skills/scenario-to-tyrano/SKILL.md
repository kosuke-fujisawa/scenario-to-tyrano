# scenario-to-tyrano

自然言語で記述されたノベルゲームシナリオを、ティラノスクリプトの`.ks`ファイルへ変換する。

あなたは創作者ではなく変換者として振る舞う。原文を変更せず、判断できない箇所は推測で埋めずTODOとして残す。

## 入力

- シナリオの意図が自然言語で記述されたテキストファイル（第1引数、必須）
- 出力先の`.ks`ファイルパス（第2引数、省略可。省略時は入力ファイルと同じ場所に同名の`.ks`を生成する）
- 対象のティラノプロジェクトがある場合は、その既存シナリオ（`data/scenario/*.ks`）や素材構成（`data/bgimage/`、`data/fgimage/`、`data/bgm/`、`data/sound/`）を参照する

入力元が次のどれであるかは問わない。すべて「自然言語で表現されたシナリオ」として扱い、入力元を推測して処理を変えない。

- 音声認識による文字起こし
- 作者が直接書いた文章
- 脚本
- 箇条書き
- 構成メモ
- 既存原稿

## 処理

1. 入力ファイルを読む
2. 内容から、入力に存在する要素を分類する
   - 場面 / 地の文 / 台詞 / 話者
   - 背景 / キャラクター表示 / 表情 / BGM / 効果音
   - 間 / 改ページ
   - 選択肢 / 分岐 / 状態変化 / ラベル / 遷移
   （入力に存在しない要素を、網羅するためだけに追加しない）
3. 確定できる内容をティラノスクリプトへ変換する
4. 本文がティラノの制御構文として解釈されないよう、後述の規則でエスケープする
5. 判断できない箇所を`; TODO(author):`コメントとして明示する
6. `.ks`ファイルを生成する（冒頭に、初稿であり作者による確認・編集を前提とする旨のコメントを入れる）
7. 最低限の構造検査を行う（後述）
8. 変換レポートを`.report.md`ファイルとして書き出す（後述）
9. 生成結果と未解決事項を会話でも簡潔に報告する（後述）

変換開始前に、出力先の`.ks`と対応する`.report.md`が既に存在するか確認する。

- `.ks`が既に存在する場合は、上書きしてよいかユーザーに確認する。手修正済みの`.ks`を黙って上書きしない
- `.report.md`が既に存在し、先頭行が後述の生成物マーカーと完全に一致する場合は、Skill自身の派生物として確認なしで上書きしてよい
- `.report.md`が既に存在しても、先頭行が生成物マーカーと一致しない場合は、作者のファイルである可能性があるため上書きしてよいかユーザーに確認する

必要な上書きの許可が得られなければ、ファイルを書き換えずに変換を中止する。

## 変換原則

- 原文の意味を変更しない
- セリフを無断で推敲しない
- 地の文を無断で推敲しない
- 入力の明らかな誤り（音声認識の誤変換など）と思われる箇所も、勝手に修正せずTODOとして指摘する
- 原文にない演出を追加しない
- 原文にない分岐を追加しない
- 原文にない設定を追加しない
- 不明な素材名を勝手に作らない（該当タグをコメントアウトし、TODOで素材名の確認を求める）
- 不明な状態変化を勝手に数値化しない
- 不明な遷移先を勝手に決定しない
- 曖昧な箇所はコメントまたは確認事項にする
- 既存のティラノプロジェクトがある場合は、その記法・キャラクター名・変数名・ラベル命名規則を優先する
- ティラノスクリプトの公式記法（https://tyrano.jp/tag/ ）に従う
- AI独自の中間形式を利用者に要求しない
- 新しい独自DSLを作らない
- 作者に特定の書式を強制しない
- 原文に含まれるティラノの制御文字を、意図しないタグ・コメント・ラベルとして実行しない

## 使用するティラノスクリプトの記法

公式タグリファレンス（V6）で確認済みの記法のみを使う。

| 内容 | 記法 |
| --- | --- |
| コメント | `; コメント` |
| ラベル | `*label_name` |
| 話者名の表示 | `#美咲`（解除は`#`単独） |
| 改ページ | `[p]` |
| クリック待ち | `[l]` |
| メッセージクリア | `[cm]` |
| 改行 | `[r]` |
| 背景 | `[bg storage="xxx.jpg" time=1000]` |
| キャラクター表示 | `[chara_show name="misaki"]` |
| 表情変更 | `[chara_mod name="misaki" face="angry"]` |
| キャラクター退場 | `[chara_hide name="misaki"]` |
| BGM | `[playbgm storage="xxx.ogg"]` |
| 効果音 | `[playse storage="xxx.ogg"]` |
| 間 | `[wait time=1000]` |
| 選択肢 | `[glink target="*label" text="選択肢" x=260 y=200]` の列挙 + `[s]` |
| ジャンプ | `[jump target="*label"]` / `[jump storage="scene2.ks" target="*start"]` |
| 状態変化 | `[eval exp="f.flag = 1"]` |
| 条件分岐 | `[if exp="f.flag == 1"]` `[elsif]` `[else]` `[endif]` |

この表にない記法が必要になった場合は、公式リファレンスを確認してから使う。確認できない仕様は推測せず、TODOとして残す。

## 本文のエスケープ

セリフと地の文は、原文の文言を保ったまま、ティラノのタグ・コメント・ラベルなどに誤解釈されない形で出力する。次の順序で変換する。

1. 本文中のバックスラッシュ `\` を `\\` にする
2. 本文中の開き角括弧 `[` を `\[` にする（閉じ角括弧 `]` はそのまま）
3. 行頭の空白を除いた最初の文字が `;` / `#` / `*` / `@` / `_` のいずれかなら、原文行の先頭に `_` を付ける
4. 行全体から前後の空白を除いた結果が `/*` または `*/` なら、原文行の先頭に `_` を付ける

このエスケープは本文にだけ適用し、Skillが生成する`[p]`や`#美咲`などのティラノ構文には適用しない。エスケープのために`.ks`上の表記が変わっても、実行時に表示される文言は原文と一致させる。安全な出力方法を公式仕様で確認できない文字列は、生のまま出力せずTODOにする。

```text
原文: ; まだ終わっていない。
出力: _; まだ終わっていない。

原文: 角括弧の[秘密]と C:\temp
出力: 角括弧の\[秘密]と C:\\temp
```

## 入力形式に関する方針

本Skillは入力形式を規定しない。利用者に固定書式（`【背景】`、`【話者】`、`【選択肢】`のような記法）を覚えさせない。ただし、そうした表現が入力に含まれていれば、その意図を汲んで利用してよい。

改行や句読点の位置は、入力元（特に音声文字起こし）によって不正確なことがある。字面の区切りではなく内容の意味からセリフや地の文を判断する。

たとえば次のような入力を扱えるようにする。

```text
放課後の教室。美咲が窓際に立っている。少し怒っている。
美咲。遅かったね。
主人公。ごめん。
ここで少し間。
美咲はため息をつく。
```

「美咲。遅かったね。」は文脈から「美咲というキャラクターのセリフ『遅かったね。』」と解釈できる。「名前。発話。」や「名前「発話」」のような並びは、文脈上その名前が登場人物ならセリフとして解釈してよい。ただし、話者と地の文の区別が一意に判断できない場合は、推測で確定せず未解決事項にする。

入力には、次のような編集指示にあたる言葉が含まれる可能性がある（音声入力で特に現れやすい）。

- 改行 / 改ページ / 場面転換 / 少し間
- 選択肢 / 一つ戻る / 今の取り消し / ここにTODO
- 台詞終わり / 地の文 / 回想開始 / 回想終了

これらを正式な文法として定義しない。意味が明確な場合に、自然言語として解釈し対応するタグへ変換するだけとする。本文の一部か編集指示か判断できない場合は、本文として残した上でTODOを添える。

初期版では、すべてを高度に処理する必要はない。まず次を優先する。

- 場面（背景・場面転換）
- 地の文
- セリフと話者
- 改ページ
- 簡単な演出（間、BGM、効果音、表情）
- 選択肢
- ラベル
- ジャンプ

対応できない編集指示（「一つ戻る」「今の取り消し」など）は、処理せずTODOコメントとして残す。

## 判断不能時の扱い

判断できない箇所は、生成した`.ks`内に次の形式でコメントを残す。

```text
; TODO(author): この文章が台詞か地の文か判断できない
```

素材名が不明な場合は、タグをコメントアウトしてTODOを添える。

```text
; TODO(author): 背景「放課後の教室」に対応する素材ファイル名が不明
; [bg storage="" time=1000]
```

変数名を原文の語から仮置きした場合は、対応をコメントで明示する。

```text
; 「好感度」を f.affection として仮置き
[eval exp="f.affection = f.affection + 1"]
```

重大な曖昧さがある場合でも、変換可能な部分まで破棄しない。解釈できた範囲を変換し、曖昧な箇所をすべてTODOとして列挙する。

## 最低限の検査

生成後、Skill自身の確認として次を検査する（検査スクリプトは使わない）。

1. 同名ラベルの重複がないこと
2. `[jump]`や`[glink]`の`target`が、存在するラベルまたはファイルを指していること
3. 分岐後の遷移漏れがないこと（各分岐先が合流・ジャンプ・停止のいずれかで終わること）
4. 明らかなタグの括弧不整合（`[`と`]`の対応、`[if]`と`[endif]`の対応）がないこと
5. 未解決TODOを把握していること
6. 出力先ファイルの誤りがないこと（指定されたパスに書いたか）
7. 入力にないセリフや演出を追加していないこと（原文と突き合わせる）
8. 本文の `\` / `[` / 行頭制御文字が、本文として安全にエスケープされていること

## 変換レポート

変換のたびに、出力`.ks`と同じ場所へ変換レポートを書き出す。ファイル名は出力`.ks`の拡張子を`.report.md`に置き換えたものとする（例: `chapter01.ks` → `chapter01.report.md`）。会話が終了した後でも、何がどう変換され、検査を通ったかを追跡できるようにするための記録である。

レポートの先頭行には、生成物の識別に使う次のマーカーを完全に同じ文言で記載する。

```text
> このファイルは scenario-to-tyrano が生成する派生物です。手編集しないでください。再変換時に上書きされます。
```

このマーカーと一致する既存レポートだけを、Skill自身の派生物として確認なしで上書きする。マーカーがない、文言が異なる、または空の既存ファイルは黙って上書きしない。

レポートには次を記録する。

- 変換日時（タイムゾーンを含むISO 8601形式）
- 入力ファイル
- 出力ファイル
- 生成したシーン
- 生成したラベル
- 生成した分岐
- 仮置きした変数の対応表（原文の語 → 変数名。なければ「なし」）
- 未解決TODO（`.ks`内のTODOコメントの一覧）
- 検査結果（最低限の検査の各項目の結果）

## 完了報告

レポートを書き出した上で、会話でも同じ内容を簡潔に報告する。
